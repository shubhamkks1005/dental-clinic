# MAP (one line per file: path - what it does). Keep current. Max ~150 lines.

## docs
- docs/DESIGN.md - design rules and mockup links; every screen follows it (owner adds the file)
- docs/ACCOUNTS.md - register of accounts, tokens and where each secret is stored (never the values)

## Commands (run from repo root, Node 26 and pnpm 12)
- pnpm dev - builds web once, then runs Vite (5173, proxies /api and /hooks) + wrangler dev (8787) together
- pnpm build - Vite build to apps/web/dist + Worker bundle dry-run to apps/worker/dist (one Worker with static assets)
- pnpm check - typecheck (all packages) + eslint + prettier --check + vitest (all packages)
- pnpm db:migrate - apply packages/db/migrations to the LOCAL D1
- pnpm deploy:staging - build, then `wrangler deploy --env staging` (needs wrangler login + real IDs)
- pnpm format - prettier --write (never touches *.md or .cursor)

## CI (.github)
- .github/workflows/ci.yml - on every push: job "check" (pnpm install --frozen-lockfile, pnpm check) and job "secret-scan" (gitleaks over full history). No deploy yet. Actions pinned by commit SHA
- .github/dependabot.yml - weekly npm + GitHub Actions update PRs, minor/patch grouped, 7-day cooldown

## Gotchas (things that surprised us)
- Your terminal's default Node is nvm v16; use `nvm use system` (Homebrew Node 26) or `nvm install` before pnpm.
- TypeScript is pinned to 6.0 because typescript-eslint 8.x does not support TypeScript 7 yet.
- pnpm blocks dependency build scripts; only esbuild and workerd are allowed (pnpm-workspace.yaml).
- Wrangler local commands run via the `wr` script so its config and logs stay in apps/worker/.wrangler, not your home folder. deploy:staging uses the normal home folder so `wrangler login` works.
- pnpm 12 writes its own version into pnpm-lock.yaml (packageManager field). After changing packageManager, run `pnpm install` and commit the lockfile, or CI's frozen install fails.
- Vite build prints a harmless "use client" warning from react-router (no server rendering here).
